# CodeMender Example Workflows

This directory provides starter GitHub Actions workflows designed to help you rapidly integrate the CodeMender CLI into your target repositories. 

## Available Workflows

### 1. Basic Scan (`codemender_basic_scan.yml`)
*   **Purpose:** Executes a standard CodeMender scan against the codebase.
*   **Behavior:** Reports security findings and outputs token utilization metrics directly into the GitHub Actions run logs.
*   **Trigger:** Can be configured to run on `push`, `pull_request`, or manually via `workflow_dispatch`.

### 2. ChatOps PR Generator (`codemender-findings-pr.yml`)
*   **Purpose:** Automates the creation of a centralized Pull Request for security reviews.
*   **Behavior:** Runs a baseline scan and generates an empty PR populated with the identified security findings in the description.
*   **Trigger:** Designed to run on a schedule or manual `workflow_dispatch` to batch findings for team review.

### 3. ChatOps Commands (`codemender-chatops.yml`)
*   **Purpose:** Enables comment-driven remediation directly within the PR generated by the workflow above.
*   **Behavior:** Parses issue comments for specific commands to trigger targeted mitigation tasks via the CodeMender CLI.
*   **Supported Commands:**
    *   `/verify <ID>`: Validates a specific finding.
    *   `/fix <ID>`: Initiates an automated fix for a specific vulnerability.
*   **Trigger:** Executes on `issue_comment` creation.

---

## Usage Instructions

To deploy these workflows to a new repository:

1. Ensure the target repository has completed the Google Cloud Workload Identity Federation (WIF) setup and has the necessary secrets configured (`GCP_WORKLOAD_IDENTITY_PROVIDER` and `GCP_SERVICE_ACCOUNT`).
2. Copy the desired `.yml` files from this directory into the `.github/workflows/` directory of your target repository.
3. Modify the triggers and environment variables within the YAML files to match the specific needs of your project.
